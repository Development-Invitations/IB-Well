# Ishonchli Buxgalter Academy — Node.js версия

Тот же сайт (курсы, регистрация/вход, личный кабинет, админка), но на Node.js
вместо PHP. Данные по-прежнему хранятся в обычных JSON-файлах в папке `data/`
— никакой СУБД устанавливать не нужно.

## Шаг 0 — проверка установки (сделайте это первым делом)

После того как сайт запущен, откройте:

**`https://ваш-домен/healthcheck`**

Страница сама проверит версию Node.js, права на запись папки `data/`, наличие
всех ключевых файлов и покажет, создан ли уже администратор — всё ✅/❌,
без гаданий по скриншотам.

## Вариант А — хостинг с панелью «Node.js Selector» (cPanel и похожие)

Это самый частый случай на современном хостинге — ищите в панели пункт
«Setup Node.js App» / «Node.js Selector» / «Node.js приложения».

1. Загрузите ВСЕ файлы из этого архива в папку, которую хостинг покажет для
   вашего домена/поддомена (файловым менеджером или по FTP — как обычно).
2. В разделе «Node.js Selector»/«Setup Node.js App» создайте приложение:
   - **Application root** — папка, куда загрузили файлы
   - **Application URL** — ваш домен/поддомен
   - **Application startup file** — `server.js`
   - **Node.js version** — любая от 18 и выше
3. Нажмите **Run NPM Install** в этой же панели (на случай, если хостинг
   всё же хочет пересобрать зависимости под свою версию Node — обычно не
   обязательно, `node_modules` уже включены в архив, но кнопка безопасна).
4. Нажмите **Start App** / **Restart**.
5. Откройте `https://ваш-домен/healthcheck` — проверьте, что всё зелёное.
6. Откройте `https://ваш-домен/install`, задайте логин/пароль администратора.
7. Готово: `/` — сайт, `/register` — регистрация, `/admin/login` — админка.

## Вариант Б — VPS / сервер с SSH-доступом

```bash
# в папке проекта
npm install          # если папки node_modules нет или хотите пересобрать
PORT=3000 node server.js
```

Для постоянной работы (чтобы сайт не падал при закрытии терминала) — через PM2:

```bash
npm install -g pm2
pm2 start server.js --name ib-academy
pm2 save
pm2 startup          # чтобы поднимался автоматически после перезагрузки сервера
```

Дальше настройте реверс-прокси (Nginx/Apache) с вашего домена на порт 3000,
либо укажите нужный порт через переменную `PORT`.

## Как проверить, что на сайте именно эта версия

В футере сайта (и в html-коде как комментарий) выводится: `1.0.0-node / 2026-09-15`.

## Структура проекта

- `server.js` — точка входа, все маршруты
- `lib/db.js` — чтение/запись JSON-«базы» с блокировкой файлов
- `lib/auth.js` — регистрация/вход пользователей и отдельный вход администратора
- `lib/telegram.js` — отправка заявок в Telegram-ботов
- `views/` — HTML-шаблоны (EJS)
- `public/` — стили, скрипты, логотип, фавикон (отдаются как есть)
- `data/` — JSON-файлы с данными (курсы, статьи, пользователи, заявки, настройки, админ)

## Два уровня доступа

- **Пользователи** — `/register`, `/login`, `/account` (личный кабинет с заявками
  и датами зачисления на курс)
- **Администратор** — `/admin/login`, отдельная страница входа, отдельный
  пароль. Внутри: дашборд с аналитикой, управление заявками (статус + даты
  начала/окончания курса), редактирование курсов и блога, список
  пользователей, настройки двух Telegram-ботов (заявки на курс / на
  консультацию).

## Безопасность перед боевым запуском

- Смените `SESSION_SECRET` в `.env` (скопируйте `.env.example` → `.env`) на
  свою случайную строку.
- После первого входа в админку можно удалить или закрыть паролем страницу
  `install` — вызвать её повторно всё равно нельзя, но лишним не будет.
- Папка `data/` не должна быть доступна напрямую по URL для скачивания —
  если используете Nginx/Apache перед Node.js, добавьте правило запрета
  доступа к `/data/`.
